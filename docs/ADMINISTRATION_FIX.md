# Исправление administration 1.2.0

Требуется **исправленное ядро versionCode 60+** (`0.3.40` в подготовленной копии).
Модуль и ядро изменены вместе. Замена одного `.so` на старом APK недостаточна:
старый API не содержал операций назначения/снятия администраторов.

## Что было неисправно

- Проверка `chat_id > 0` считала личной перепиской и обычные группы,
  и супергруппы: ядро использует в том числе положительные MTProto ID.
- `.unadmin`, `.unrank`, `.rank` и подтверждение `.admin` только формировали
  сообщение об успехе. Запроса Telegram в порте не было.
- `.untag` считал `sender_id` в истории и сообщал о снятии тегов.
- Обработчик callback проверял права до проверки префикса кнопки и мог
  перехватывать кнопки других модулей.
- Ранг ограничивался 16 байтами вместо символов; кириллица обрезала лимит.
- Полные ID, права и ранг помещались в callback_data, превышая лимит Telegram.
- Размер ответа `db_get` использовался как индекс без проверки усечения буфера.

## Что изменено

Тип чата определяется по `inputPeerChat` / `inputPeerChannel` / `inputPeerUser`,
а не по знаку ID. В конец C ABI добавлены `chat_type` и `admin_action`,
сохранены старые смещения. Обновлены оба SDK и песочница Binder.
Новая версия модуля исключает загрузку на старом ядре через `min_host_version=60`.

Модуль передаёт декларативный запрос ядру. Ядро выполняет реальные
`channels.editAdmin`, `messages.editChatAdmin`, `channels.getParticipant`
и `messages.editChatParticipantRank`. Обычные группы используют свой RPC.
Смена ранга сохраняет прежние права, включая `manage_topics`.
При отсутствии старых прав `.rank` использует минимальное `change_info`,
как Python-оригинал. Ранги обычных групп отклоняются до изменения прав.

И команда, и подтверждение панели получают результат после ответа Telegram.
Ошибки Telegram отображаются пользователю. Если права сняты, но снятие тега
не удалось, показывается частичный результат, а не полное подтверждение успеха.
Проверка доверенного уровня повторяется в ядре, включая запросы песочницы.

`.untag` читает страницы участников, пропускает администраторов, создателя,
ботов и участников без тега, выполняет отдельные запросы снятия и считает
фактические ответы. Обрабатываются только участники, которых Telegram вернул
для текущего аккаунта. При `FLOOD_WAIT`/потере прав операция останавливается
с отчётом; необработанные участники указываются отдельно.

Панели используют компактные токены `adm:` и состояние в БД, ограниченное
64 слотами с временем жизни 24 часа. Проверяются автор, чат и ревизия;
подтверждение одноразовое. Чужие префиксы callback игнорируются без действий.
Прежние шаблоны прав и сохранённые конфигурации читаются в старом формате.

Дополнительно тесты выявили `stack-use-after-scope` в `core::sync_wait`:
временная coroutine-lambda уничтожалась до выполнения. Closure теперь живёт
до завершения executor. Проверены отложенные `void`/значение и оба пути исключений.

## Сборка

```bash
# Из корня KoteModules_repo; путь к новому SDK обязателен.
export ANDROID_NDK_HOME=/путь/к/android-ndk-r26d
bash tools/build_administration.sh --android
bash tools/build_chess.sh --android

# Сборка APK из соседнего исправленного kotogram/kotogram-apk:
# JAVA_HOME=... ANDROID_HOME=... gradle assembleRelease
```

Успешная Android-сборка обновляет размер, хэш и min_host_version в локальном
каталоге. Публикация не выполняется. Linux-библиотеку устанавливать на телефон нельзя.
Настройки Android SDK и подписи необходимо взять из основной рабочей копии;
секреты и ключи в отдельную копию не переносились.

## Проверки

```bash
bash tests/run_administration.sh
ASAN_OPTIONS=detect_leaks=0 bash tests/run_administration.sh --sanitize
bash tests/run_chess.sh
```

119 проверок порта и сериализованных TL-запросов: реальные положительные ID
групп, личка, обе разновидности групп, ошибки RPC, частичный результат,
сохранение прав, кириллица, страницы участников, чужие/старые/повторные кнопки.
Транспорт подменён тестовым: реальные аккаунты и права участников не затрагивались.
Для линковки использована существующая `libkotogram.a`; изменённый хост
собран из исходников.

JNI проверен на синтаксис GCC с локальными заголовками JNI и временными
объявлениями Android log/dlext. Это не Android-сборка и не тест устройства.
В доступном окружении нет NDK; сеть и SSH к серверу сборки недоступны.
Готовые APK и Android `.so` здесь пока не получены.
