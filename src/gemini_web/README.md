# Gemini Web для KoteLoader — самостоятельный ARM64-модуль

Экспериментальная версия **0.1.2**. Работа с Gemini через cookies прямо на
телефоне, без Python и сервера-посредника. Для этого текстового модуля
обновление APK не требуется; поставка 0.3.54 также добавляет общий SDK для PMBL.

Файл для установки: `../gemini_web.so` (после сборки также `build/gemini_web.so`).

## Установка и первая проверка

1. Отправить **Android ARM64** файл `gemini_web.so` в Избранное как документ.
2. Ответить `.forceinstall` для обновления установленного модуля; для первой
   установки — `.install` или выбор файла во вкладке модулей. При обновлении
   cookies, выбранная модель и память остаются в БД; повторный вход не нужен.
3. Выполнить `.gwebtest` без cookies: это проверит прямой HTTPS из `.so`.
4. В браузере войти в `https://gemini.google.com`, убедиться, что чат отвечает,
   скопировать значения `__Secure-1PSID` и, если присутствует, `__Secure-1PSIDTS`.
5. В Избранном отправить **отдельное сообщение** с PSID и необязательным PSIDTS
   через пробел или с новой строки, без имён и кавычек. Ответить на него
   `.gweblogin` **без аргументов**. Старый хост журналирует аргументы команд,
   поэтому на APK младше 74 ввод после `.gweblogin` запрещён.
   На 0.3.54 и новее можно использовать также аргументы команды в Избранном.
   После сохранения сообщение со значениями можно удалить.
6. `.gwebtest`, затем `.gweb Ответь одним словом: работает`.
7. `.gweb Какое слово ты только что написал?` — проверка продолжения диалога.
8. Перезапустить приложение и повторить вопрос — проверка восстановления.

Cookies остаются в пространстве БД модуля. В статусе и ошибках их значения,
токен страницы и сырые ответы Google не печатаются. Не присылать cookies
разработчику; для диагностики достаточно сообщения `.gwebtest`.

## Команды

| Команда | Назначение | Доступ |
| --- | --- | --- |
| `.gweblogin` ответом на PSID [PSIDTS] | Сохранить новую сессию; прежние локальные диалоги очищаются | OWNER |
| `.gweblogout` | Удалить cookies и все локальные диалоги | OWNER |
| `.gwebcookies` | Инструкция по cookies | OWNER |
| `.gweb [вопрос]` | Текстовый запрос; поддерживает reply на текст | TRUSTED |
| `.gwebclear` | Забыть диалоги всех моделей в текущем Telegram-чате | TRUSTED |
| `.gwebmodel [auto\|ключ\|id]` | Получить список моделей аккаунта или выбрать модель | OWNER |
| `.gwebstatus` | Локальный статус, без сетевой проверки | TRUSTED |
| `.gwebtest` | Проверить HTTPS и инициализацию сессии; генерация проверяется через gweb | OWNER |
| `.gwebrefresh` | Обновить cookies, токен и модели, сохранив диалоги | OWNER |
| `.gwebtimeout [30–300]` | Таймаут генерации; по умолчанию 150 секунд | OWNER |

Префикс команд берётся из настроек приложения. Префикс `.` здесь — пример.
Каждая модель имеет отдельный диалог в каждом Telegram-чате. Список моделей
приходит от Google: названия и внутренние идентификаторы не зашиты в бинарник.
`auto` оставляет выбор модели Google; конкретный вариант выбирается из списка.

## Что реализовано и что пока не проверено

- Собственный HTTP/1.1 поверх OpenSSL, включая POST, заголовки, cookies,
  chunked-ответы, gzip/deflate, ограничение размера и сетевые таймауты.
- Проверка сертификата и имени сервера. На Android загружаются системные CA
  из активного Conscrypt APEX или `/system/etc/security/cacerts`.
  Проверка TLS не отключается даже при ошибке сертификата.
- Инициализация из HTML (`SNlM0e`, build label, session ID), запрос состояния
  аккаунта и моделей, `StreamGenerate`, разбор JSON/JSPB-фреймов.
- Продолжение диалога через metadata, включая context token; сохранение между
  вызовами и перезапусками. Смена Google-сессии не наследует старые диалоги.
- Cookies обновляются при активном использовании, раз в десять минут при
  необходимости, либо по `.gwebrefresh`. Фонового потока для продления cookies
  во время простоя нет. В некоторых случаях потребуется повторный вход.
- Обработка сессии сериализована; APK также может ставить следующую команду
  в очередь. `ctx` не используется после выхода из обработчика.
- Ошибка сети/лимита не очищает диалог. POST генерации автоматически повторно
  не отправляется: это предотвращает дублирование запроса при неопределённом
  результате. Пользователь сам решает, повторять ли команду.
- Длинные ответы разбиваются по UTF-16 с сохранением текста; особо длинные
  отправляются файлом, если хост предоставляет каталог кэша и отправку файла.

**Пока поддерживается текст. Фото, аудио, видео, документы, генерация медиа,
Gems и Deep Research не реализованы.** Markdown в сообщениях превращается
в текст с Telegram entities; в длинном текстовом файле сохраняется оригинал.
Модуль не включён для твинков.

TLS-клиент не копирует отпечаток Chrome из `curl_cffi`. Google может потребовать
другое сетевое поведение: это выясняется реальным тестом на устройстве.
Собственный транспорт использует обычный маршрут Android/VPN. Настроенный
только для Telegram прокси приложения на эти HTTPS-запросы не распространяется.

Исходный локальный `koteloader.apk` проверен через `aapt2`: версия 0.3.50,
versionCode 70, INTERNET разрешён, `:modsandbox` имеет `isolatedProcess=false`.
Это подтверждает наличие необходимых разрешений в этом APK, но не заменяет
запуск на устройстве. Версию на телефоне автоматически проверить не удалось.

В среде сборки внешний DNS и ADB недоступны. Пользователь подтвердил загрузку,
реальную генерацию и выбор модели версии 0.1.1 на Android 24 октября 2026 года.
Версия 0.1.2 проверена локальными тестами; новый интерфейс на телефоне пока
не проверен. Настоящие cookies пользователя в тестах не использовались.

В APK до 74 скачивание reply-вложений привязано к нескольким встроенным
командам. APK 0.3.54 добавляет общий ленивый доступ к файлам в SDK. Перенос
загрузки медиа в Google остаётся отдельной задачей: один новый API Telegram
сам по себе её не реализует.

## Диагностика

| Этап ошибки | Что проверять |
| --- | --- |
| `permission` | Android запретил прямую сеть; проверить точную версию APK |
| `dns`, `connect`, `timeout` | Интернет, системный VPN, доступность Gemini |
| `certificates`, `certificate` | Системные корневые сертификаты, дату, VPN |
| `handshake`, `send`, `receive` | Соединение или совместимость TLS-клиента |
| `auth`, `account` | Вход и условия сервиса в браузере; актуальность cookies |
| `http403` | Ограничение сессии, сети или клиента; это не обязательно истёкшие cookies |
| `quota`, `upstream` | Лимит аккаунта или временная ошибка Google; история сохранена |
| `protocol`, `incomplete`, `empty` | Изменение протокола или незавершённый ответ |

Токены, cookies, содержимое запросов и сырые сетевые ответы для отчёта не нужны.

## Сборка и проверки

```bash
bash build.sh --test
bash build.sh --sanitize
bash build.sh --host
bash build.sh --android
```

Для `--sanitize` включены AddressSanitizer и UndefinedBehaviorSanitizer.
LeakSanitizer по умолчанию отключён из-за запрета ptrace в среде сборки;
при запуске вне неё можно задать `ASAN_OPTIONS=detect_leaks=1`.

Зависимости находятся в существующем проекте. Можно переопределить:

- `KOTO_SDK_INCLUDE` — каталог с `module_abi.h` и `nlohmann/json.hpp`;
- `GWEB_ANDROID_OPENSSL` — Android ARM64 OpenSSL, подкаталоги `include/`, `lib/`;
- `ANDROID_NDK_HOME` — NDK 26.3.11579264;
- `CXX` — компилятор Linux для тестов.

Android-сборка содержит OpenSSL и C++ runtime статически. Внешние зависимости:
только стандартные Android `libc`, `libm`, `libdl`, `libz`. ELF имеет 16 КиБ
выравнивание LOAD-сегментов и экспорт `koto_module_register`. Отчёт и SHA-256
записываются в `build/gemini_web.build.json`.

Тесты проверяют фрагментацию HTTP, сжатие, обрыв потока, RPC-конверты, накопительные
ответы, metadata, UTF-16, область cookies, их ротацию и удаление, разделение
аккаунтов/моделей/чатов, отсутствие повторного POST после ошибки и команды
через реальный дескриптор ABI. Настоящее TLS-соединение тестируется через
`socketpair` с временным тестовым CA: корректный сертификат принимается,
неверное имя и недоверенный CA отклоняются. В бинарник тестовый CA не включён.

## Источники сведений о протоколе

Реализация написана на C++ и не включает Python-код `gemini-webapi`.
Для сверки полей протокола использовались опубликованные сведения:

- <https://github.com/HanaokaYuzu/Gemini-API>
- <https://github.com/etrnkz/gemini-unofficial-api/blob/main/docs/protocol.md>

Сведения о протоколе актуальны для исследования 23 октября 2026 года;
живой Google-запрос из этой реализации ещё не подтверждён.

Сторонние компоненты: OpenSSL 3 (Apache-2.0), LLVM libc++ (Apache-2.0 с LLVM
exceptions), nlohmann/json (MIT; уведомление в заголовке SDK), системный zlib
(zlib license). Уведомления приложены в каталоге `licenses/`.

## Исправление 0.1.1

Google может не возвращать необязательный AccountStatus. Отсутствие/null теперь
обрабатывается согласно upstream как доступная инициализация, явные коды отказа
по-прежнему отклоняются. Поддерживается разреженный JSPB с полями в последнем
объекте массива. `.gwebtest` проверяет HTTPS/инициализацию; реальную генерацию
проверяет `.gweb привет`. Это не обещание действительности любых cookies.

На APK 0.3.54 / versionCode 74 стандартный журнал хоста больше не пишет аргументы
команд: разрешён также `.gweblogin <PSID> [PSIDTS]` в Избранном. Старые APK
по-прежнему требуют reply на отдельное сообщение с cookies без аргументов.
При обновлении `.so` сохранённые cookies и диалоги остаются в БД модуля.

Пройдены 336 проверок, включая ASan/UBSan. Внешние запросы с настоящими cookies
и Android runtime в среде сборки не проверялись. Мультимодальные вложения
в этой версии ещё не реализованы; поддерживается текст и история диалога.

## Интерфейс 0.1.2

- Сразу перед генерацией собственная команда меняется на «✦ Gemini · Думаю…».
  Проверка подключения, моделей и обновление сессии тоже имеют промежуточный
  статус. По завершении показывается ответ либо ошибка. Используется уже
  существующий live c_edit APK; новая APK для этого изменения не требуется.
  Входящую команду доверенного пользователя модуль не редактирует: готовый
  ответ приходит reply. Немедленный reply-статус текущий ABI не предоставляет.
- Заголовки, жирный/курсивный текст, ссылки, списки, цитаты и код преобразуются
  в Telegram entities. Закрытые выделения разбираются; непарные маркеры
  сохраняются как буквальный текст. Это ограниченный Markdown, не полный
  CommonMark: таблицы/LaTeX остаются текстом, HTML не интерпретируется.
- Блок кода разбирается целиком до деления ответа: каждая часть длинного Lua
  остаётся PRE, без видимых тройных backtick и строки языка. Содержимое кода,
  отступы, `snake_case`, звёздочки и эмодзи внутри кода не переписываются.
  Подсветка конкретного языка через существующий ABI не гарантируется.
- Сначала разбирается разметка, затем текст делится по UTF-16 и диапазоны entities
  переносятся в каждую часть. Учитываются символы вне BMP, лимит количества
  entities и заголовок первого сообщения. Недопустимое вложение украшений в
  CODE/PRE не отправляется. Правила: [Telegram entities](https://core.telegram.org/api/entities).
- По запросу владельца используются custom emoji: ✅ 5774022692642492953,
  ❌ 5774077015388852135, 🧹 5845945815549350824. Замены действуют в служебных
  сообщениях и обычном тексте ответа, сохраняя стандартный символ как fallback.
- HTTP/TLS, протокол Google и формат сохранённых диалогов не менялись.

Проверки 0.1.2 включают форматирование через настоящий дескриптор модуля,
правильные ID premium-эмодзи, появление статуса до запроса, замену его ошибкой,
длинные блоки кода, ссылки со скобками, вложенные выделения и разбиение рядом
с surrogate pair. Результаты и SHA находятся в VALIDATION.json и build metadata.
